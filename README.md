# Digital Circuits Suite

A framework-free educational application containing three interactive tools for learning digital logic design, plus an AI-powered backend for natural-language Boolean problem solving.

## Architecture

```
Digital Circuits Suite
├── Root        — Landing page / circuit sandbox
├── Web1        — Boolean Logic Solver
├── Web2        — Combinational Circuits Simulator (18 circuits)
├── Web3        — 7-Segment Display Simulator
├── Backend     — FastAPI + Gemini AI service
└── shared/     — Shared TypeScript Boolean engine
    └── ts/
        ├── boolean/    — AST, tokenizer, parser, minimizer, formatter
        └── exporters/  — Verilog, C/C++, LaTeX code generators
```

### Design Decisions

- **No frontend framework.** Pure TypeScript + HTML + CSS + SVG.
- **TypeScript is the source of truth.** `script.js` files are committed compiled artifacts generated by esbuild.
- **Shared Boolean engine.** The parser, Quine-McCluskey minimizer, and exporters live in `shared/ts/` and are bundled into each app.
- **Static deployment.** Each page loads its own self-contained bundle — no server needed for the frontend.
- **AI backend decouples LLM from truth.** The Gemini LLM translates natural language to structured Boolean problems; a deterministic parser and exhaustive verification produce the final answer.

## Boolean Solver Architecture

```
User Input (expression / minterms / maxterms / truth table / word problem)
    ↓
Tokenizer → Parser → AST (canonical representation)
    ↓
Quine-McCluskey Minimizer (SOP + POS)
    ↓
Simplified AST → Formatter (display string)
    ↓
                    ┌───────────┬───────────┬───────────┐
                    ↓           ↓           ↓           ↓
              Truth Table    K-Map     Circuit Graph  Code Export
                             + SVG       (AND/OR/NOT    (Verilog,
                                         NAND, NOR)      C, LaTeX)
```

### Key Properties

- **Single source of truth:** The AST is the canonical representation. All outputs (truth table, K-map, circuits, exports) derive from it.
- **Exhaustive verification:** After minimization, every possible input combination is evaluated to confirm the simplified expression matches the original function.
- **Correctness guarantee:** The application never knowingly displays, exports, or teaches an incorrect Boolean result.

## AI Backend Architecture

```
User Question
    ↓
Input Validation (size limits, structure check)
    ↓
Deterministic Parser (detects explicit Σm/Σd → bypasses LLM)
    ↓  [if natural language]
Gemini LLM (structured JSON output with schema enforcement)
    ↓
Strict Validation (variable names, expression parsing, minterm consistency)
    ↓
Deterministic Evaluator (exhaustive 2^n truth table generation)
    ↓
Verification (LLM minterms vs evaluated minterms must match)
    ↓
Final Answer → Frontend
```

### AI Safety Measures

- LLM output is never trusted without mathematical verification
- Gemini responses use structured JSON schema enforcement
- All expressions are parsed and evaluated deterministically
- Explicit Σm/Σd inputs bypass the LLM entirely
- Request size limits, timeouts, and variable-count limits prevent abuse
- All LLM-generated text is rendered via `textContent`, not `innerHTML`

### Backend Architecture

```
Backend/
├── backend.py          — Entry point (re-exports from main.py)
├── main.py             — FastAPI routes + initialization
├── config.py           — Safety limits (mirrors shared/ts/boolean/limits.ts)
├── models.py           — Pydantic request/response models
├── parser.py           — Deterministic Σm/Σd parser (no Gemini)
├── ai_solver.py        — Gemini interaction + prompt building
├── boolean_engine.py   — Expression evaluation + minterm generation
├── .env.example        — Template for environment variables
└── requirements.txt    — Python dependencies
```

### Request Flow

```
User Question
     ↓
Input Validation (length, complexity limits)
     ↓
┌─ Explicit Σm/Σd? ──→ parser.py (deterministic, no Gemini)
│
└─ Natural language? ──→ ai_solver.py (Gemini call)
                              ↓
                    Structured JSON (enforced by response_schema)
                              ↓
                    boolean_engine.py (deterministic verification)
                              ↓
                    Retry once if verification fails
                              ↓
                         Final Answer
```

## Web1 — Boolean Logic Solver

Supports all standard Boolean algebra operations:

- **Input modes:** Expression, minterms, maxterms, don't-cares, truth table, AI word problems
- **Analysis:** Truth table, canonical SOP/POS, Quine-McCluskey minimization
- **Visualization:** Karnaugh maps with Gray-code ordering and implicant overlays
- **Circuit synthesis:** AND/OR/NOT, NAND-only, NOR-only implementations
- **Live probing:** Click input pins to toggle values and see real-time wire coloring
- **Code export:** Verilog HDL, C/C++, LaTeX
- **Constants:** Supports 0 and 1 as Boolean constants
- **Multi-character variables:** PIN, RESET_N, ENABLE, DATA0, etc.

## Web2 — Combinational Circuits Simulator

18 interactive combinational circuits organized in 6 categories:

1. **Adders:** Half Adder, Full Adder, 4-Bit Ripple Carry Adder
2. **Subtractors:** Half Subtractor, Full Subtractor, 4-Bit Ripple Borrow Subtractor
3. **Multiplexers:** 2:1, 4:1, 8:1 MUX
4. **Demultiplexers:** 1:2, 1:4, 1:8 DEMUX
5. **Decoders & Encoders:** 2:4 Decoder, 3:8 Decoder, 4:2 Priority Encoder, 8:3 Priority Encoder
6. **Arithmetic:** BCD Adder, 4-Bit Magnitude Comparator

Features: live wire signal tracing, ripple propagation animation, timing diagram oscilloscope, Verilog export.

## Web3 — 7-Segment Display Simulator

- **Modes:** Interactive and Counter (automated)
- **Encoding:** BCD (0–9) and Full Hexadecimal (0–F)
- **Polarity:** Common Cathode and Common Anode
- **Analysis:** Truth tables, Karnaugh maps, Boolean expressions (derived from HEX_PATTERNS via QM minimizer)
- **Verilog export:** Synthesizable decoder module
- **Direct keyboard input:** Press 0–F to drive the display
- **Segment timing diagram:** Real-time digital waveform analyzer
- **LED phosphor customizer:** Multiple color themes

| Module | Purpose |
|--------|---------|
| `boolean/ast.ts` | Canonical AST types, evaluation, truth table generation |

## Safety Limits

| Limit | Value | Rationale |
|-------|-------|-----------|
| Max variables | 8 | 2^8 = 256 rows is the practical UI limit |
| Max expression length | 2000 chars | Prevents tokenization DoS |
| Max problem description | 4000 chars | Prevents LLM API abuse |
| QM node budget | 200,000 | Prevents browser freeze on large functions |

## Deployment

The application deploys as static files:

1. Run `npm run build` to compile all TypeScript
2. Deploy the root directory (including `Web1/`, `Web2/`, `Web3/`, `Backend/`)
3. The frontend requires no server — just serve the static files
4. The backend requires a Python server with Gemini API access

## Contributing

1. TypeScript is the source of truth — never edit `script.js` directly
2. Run `npm run build` after any TypeScript changes
3. Run `npm test` before committing
4. Run `npm run check:shared` to verify shared scripts haven't drifted
5. The Boolean minimizer (Quine-McCluskey) has been verified against extensive test suites — do not replace without equivalent verification
6. All LLM output is untrusted — never display without deterministic verification
